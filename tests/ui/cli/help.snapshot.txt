Usage: wetterdienst [OPTIONS] COMMAND [ARGS]...

  Weather, climate and hydrology data from national weather services, in one interface.

  A typical session finds a provider's network, then a station, then reads its data:

      wetterdienst providers
      wetterdienst stations --provider=dwd --network=observation --parameters=daily/kl --name=Dresden-Klotzsche
      wetterdienst values --provider=dwd --network=observation --parameters=daily/kl --stations=01048 --timestamp=2020-05

  Run `wetterdienst COMMAND --help` for a command's options and examples.

Options:
  -v, --version  Show the version and exit.
  --help         Show this message and exit.

Commands:

  auth         Check whether the credentials for a provider and network are present and accepted.
  cache        Display cache location.
  coverage     Get the resolutions, datasets and parameters of one network.
  fields       Describe the fields of a dataset's files, from the provider's own documentation.
  glossary     Look up what a parameter measures and which unit it is returned in.
  history      Acquire station history.
  info         Display project information.
  interpolate  Interpolate data for a point from the stations around it.
  issues       List available issue (model-run) datetimes for a station.
  kostra       Acquire DWD's design rainfall (KOSTRA: return periods of heavy rain) at a point.
  providers    List the providers and their networks, and describe what each provider is.
  radar        List radar stations.
  restapi      Start the Wetterdienst REST API web service.
  station-ids  Find one WMO number, WIGOS identifier or ICAO code at every provider that has it.
  stations     Acquire stations.
  statistics   Count, average, add up or take the extremes of each station's values per year,...
  storm-cells  Acquire DWD's thunderstorm cells (KONRAD3D).
  summarize    Summarize data for a point: the nearest station's value.
  values       Acquire data.

  With --target the extension decides the format (.json, .geojson, .csv), as for the other commands.

                                  (an edge counts as inside): the reliable way to ask about one

                                  snapshot without a warning still writes the file. Example:
                                  file://alerts.csv

  --pretty BOOLEAN                Pretty-print JSON with 4-space indentation, as REST's pretty=true.

  --with-metadata BOOLEAN         Write the metadata block (provider, licence, credit line, date of
                                  the data) beside the --target file as <file>.metadata.json. A
                                  .json or .geojson file holds it already; a .csv file does not.
                                  Needs --target. Default: false
  --debug BOOLEAN                 Log at debug level. Default: false
  --quiet BOOLEAN                 Log errors and warnings about the answer only: no progress. Not
                                  with --debug. Default: false
  --help                          Show this message and exit.

  # the warnings active at a past time: replace YYYY-MM-DDTHH:MM with one within the last
  # ~48 hours, all DWD keeps

  # to a GeoJSON file
  wetterdienst alerts --format=geojson --target=file://alerts.geojson


$ wetterdienst auth --help

Usage: wetterdienst auth [OPTIONS]

  Check whether the credentials for a provider and network are present and accepted.

  Prints `{"provider", "network", "auth", "configured", "valid"}`. `auth` is whether the network
  needs credentials, `configured` whether they are present, and `valid` whether the provider
  accepted (true) or rejected (false) them. `valid` is false where they are not configured, and null
  where the check could not tell (no network, a timeout, a rate limit, an outage of the provider):
  unknown, not rejected. A network that needs none is configured and valid.

  This is the one command that probes the provider, for the one network asked about: a single
  attempt that gives up after a few seconds. `providers` does not probe and has no `valid`, only
  whether the credentials are `configured`. The exit code is 0 whatever `valid` is: read the answer.

Options:
  --provider TEXT  Data provider/organisation. List the provider/network combinations with:
                   wetterdienst providers. Examples: dwd, eccc, noaa, wsv, ea, eaufrance, nws,
                   geosphere  [required]
  --network TEXT   Data network of the provider. Examples: observation, mosmix, radar, ghcn, pegel,
                   hydrology  [required]
  --debug BOOLEAN  Log at debug level. Default: false
  --quiet BOOLEAN  Log errors and warnings about the answer only: no progress. Not with --debug.
                   Default: false
  --help           Show this message and exit.

  Examples:

  # whether the credentials this installation holds for a provider are present and accepted
  wetterdienst auth --provider=aemet --network=observation

  # a network that needs none is configured and valid without a request
  wetterdienst auth --provider=dwd --network=observation

$ wetterdienst kostra --help

Usage: wetterdienst kostra [OPTIONS]

  Acquire DWD's design rainfall (KOSTRA: return periods of heavy rain) at a point.

  Reads KOSTRA-DWD-2020 and returns the table of the cell of DWD's 5 km grid that holds the point:
  for each duration of a rain (5 minutes to 7 days) and each return period (1 to 100 years), its
  depth in mm, its intensity in l/(s ha) and DWD's uncertainty in plus-minus percent, with the
  cell's INDEX_RC and the position of its centre. Pass --duration, and --return-period, for the one
  value you need: a duration reads one table of DWD, without it all 22 are read. A point outside
  Germany and a border of about 10 km, or in the sea, is refused.

Options:
  --latitude FLOAT RANGE   Latitude of the point. DWD's grid covers Germany and a border of about 10
                           km.  [-90<=x<=90; required]
  --longitude FLOAT RANGE  Longitude of the point.  [-180<=x<=180; required]
  --duration INTEGER       Only this duration of the rain, in minutes: 5, 10, 15, 20, 30, 45, 60,
                           90, 120, 180, 240, 360, 540, 720, 1080, 1440, 2880, 4320, 5760, 7200,
                           8640 or 10080 (7 days). Without it all 22 are read: 22 files of DWD,
                           which takes 2 s the first time and is then served from the cache.
  --return-period INTEGER  Only this return period, in years: 1, 2, 3, 5, 10, 20, 30, 50 or 100.
                           Default: all nine.
  --format [json|csv]      Output format: json (with the cell and the metadata block) or csv (the
                           table alone). Default: json
  --pretty BOOLEAN         Pretty-print JSON with 4-space indentation, as REST's pretty=true.
                           Default: false
  --debug BOOLEAN          Log at debug level. Default: false
  --quiet BOOLEAN          Log errors and warnings about the answer only: no progress. Not with
                           --debug. Default: false
  --help                   Show this message and exit.

  Examples:

  # the 60-minute rain that comes once in 100 years at a point in Berlin: the depth (mm), the intensity (l/(s ha))
  # and DWD's uncertainty (+- %), as JSON with the grid cell
  wetterdienst kostra --latitude=52.52 --longitude=13.40 --duration=60 --return-period=100

  # every return period of one duration, as CSV
  wetterdienst kostra --latitude=48.14 --longitude=11.58 --duration=120 --format=csv

  # the whole table of the cell: 22 durations and 9 return periods (22 files of DWD: 2 s the first time)
  wetterdienst kostra --latitude=53.55 --longitude=9.99

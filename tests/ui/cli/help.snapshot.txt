Usage: wetterdienst [OPTIONS] COMMAND [ARGS]...

  Weather, climate and hydrology data from national weather services, in one interface.

  A typical session finds a provider's network, then a station, then reads its data:

      wetterdienst about coverage
      wetterdienst stations --provider=dwd --network=observation --parameters=daily/kl --name=Dresden-Klotzsche
      wetterdienst values --provider=dwd --network=observation --parameters=daily/kl --stations=01048 --timestamp=2020-05

  Run `wetterdienst COMMAND --help` for a command's options and examples.

Options:
  -v, --version  Show the version and exit.
  --help         Show this message and exit.

Commands:
  about        Get information about the data.
  alerts       Acquire DWD weather alerts (CAP warnings).
  cache        Display cache location.
  history      Acquire station history.
  info         Display project information.
  interpolate  Interpolate data for a point from the stations around it.
  issues       List available issue (model-run) datetimes for a station.
  radar        List radar stations.
  restapi      Start the Wetterdienst REST API web service.
  stations     Acquire stations.
  stripes      Climate stripes.
  summarize    Summarize data for a point: the nearest station's value.
  values       Acquire data.

$ wetterdienst about auth --help

Usage: wetterdienst about auth [OPTIONS]

  Check whether the credentials for a provider and network are present and accepted.

  Prints `{"provider", "network", "auth", "configured", "valid"}`. `auth` is whether the network
  needs credentials, `configured` whether they are present, and `valid` whether the provider
  accepted (true) or rejected (false) them. `valid` is false where they are not configured, and null
  where the check could not tell (no network, a timeout, a rate limit, an outage of the provider):
  unknown, not rejected. A network that needs none is configured and valid.

  This is the one command that probes the provider, for the one network asked about: a single
  attempt that gives up after a few seconds. `about coverage` does not probe and has no `valid`,
  only whether the credentials are `configured`. The exit code is 0 whatever `valid` is: read the
  answer.

Options:
  --provider TEXT  Data provider/organisation. List the provider/network combinations with:
                   wetterdienst about coverage. Examples: dwd, eccc, noaa, wsv, ea, eaufrance, nws,
                   geosphere  [required]
  --network TEXT   Data network of the provider. Examples: observation, mosmix, radar, ghcn, pegel,
                   hydrology  [required]
  --debug BOOLEAN  Log at debug level. Default: false
  --help           Show this message and exit.

  Examples:

  # whether the credentials this installation holds for a provider are present and accepted
  wetterdienst about auth --provider=aemet --network=observation

  # a network that needs none is configured and valid without a request
  wetterdienst about auth --provider=dwd --network=observation

$ wetterdienst alerts --help

Usage: wetterdienst alerts [OPTIONS]

  Acquire DWD weather alerts (CAP warnings).

  Returns all warnings active at the selected time (the latest snapshot by default), one row per
  alert, with a GeoJSON MultiPolygon geometry. An empty result means there were no active warnings.

Options:
  --granularity [community|district]
                                  Spatial granularity: 'community' (per Gemeinde, default) or
                                  'district' (per Landkreis).
  --language [de|en|es|fr|mul]    Language of the warning texts. Default: en
  --timestamp TEXT                Point in time (ISO 8601, UTC if no offset) to select the active-
                                  warnings snapshot for. Defaults to the latest snapshot. Must fall
                                  within DWD's rolling ~48-hour window.
  --format [json|geojson|csv]     Output format. Default: json
  --target TEXT                   Write output to this file instead of stdout. Example:
                                  file://alerts.geojson
  --pretty BOOLEAN                Pretty-print JSON with 4-space indentation, as REST's pretty=true.
                                  Default: false
  --debug BOOLEAN                 Log at debug level. Default: false
  --help                          Show this message and exit.

  Examples:

  # current warnings per community (Gemeinde), as JSON
  wetterdienst alerts

  # per district (Landkreis), as GeoJSON, in German
  wetterdienst alerts --granularity=district --language=de --format=geojson

  # the warnings active at a past time: replace YYYY-MM-DDTHH:MM with one within the last
  # ~48 hours, all DWD keeps
  wetterdienst alerts --granularity=district --timestamp=YYYY-MM-DDTHH:MM

  # to a GeoJSON file
  wetterdienst alerts --format=geojson --target=file://alerts.geojson

$ wetterdienst stations --help

Usage: wetterdienst stations [OPTIONS]

  Acquire stations.

  Select them with exactly one of --all, --stations, --name, --latitude/--longitude with --rank or
  --distance, --left/--bottom/--right/--top, or --sql. Given a window, with --timestamp or --start /
  --end, only the stations whose record overlaps it are listed.

  A selection that finds no station is no failure: the list is empty, the command says so on stderr
  and exits 0. A station id of --stations the network has no station for is named in a warning and
  left out.

Options:
  --provider TEXT                 Data provider/organisation. List the provider/network combinations
                                  with: wetterdienst about coverage. Examples: dwd, eccc, noaa, wsv,
                                  ea, eaufrance, nws, geosphere  [required]
  --network TEXT                  Data network of the provider. Examples: observation, mosmix,
                                  radar, ghcn, pegel, hydrology  [required]
  --parameters TEXT               Parameters as resolution/dataset or resolution/dataset/parameter,
                                  comma-separated. Examples: daily/kl,
                                  daily/climate_summary/precipitation_amount  [required]
  --periods TEXT                  Dataset periods, comma-separated. Inferred from the timestamp when
                                  one is given, else every period the requested datasets publish;
                                  one they are not published under is rejected. Examples:
                                  historical, recent, now
  --timestamp TEXT                Single date or interval in ISO 8601 format, covering everything it
                                  names: 2020-05-01 is that whole day, 2020-05 the month and 2020
                                  the year, while a date carrying a time (2020-05-01T12) is that one
                                  instant. Examples: 2020-05-01, 2020-05, 2020-05-01/2020-05-05.
                                  Given, only the stations whose record overlaps it are listed: one
                                  that started after the window is left out, and so is one that
                                  ended before it by more than the buffer (--station-window-end-
                                  buffer), the end a source publishes lagging a station still
                                  reporting
  --start TEXT                    Start of a time window, instead of --timestamp. Given alone, it is
                                  read as --timestamp.
  --end TEXT                      End of a time window. Given alone, it is read as --timestamp.
  --all BOOLEAN                   Select all stations. Default: false
  --stations TEXT                 Select stations by id, comma-separated. Example: 01048,04411
  --name TEXT                     Select stations by fuzzy name match: the best five for `stations`,
                                  which lists candidates, the best one for `values`, unless --rank
                                  says, among the stations with a record in --timestamp if given.
                                  Example: Dresden-Klotzsche
  --name-threshold FLOAT RANGE    Minimum fuzzy-match score for --name (0 = any match, 1 = exact).
                                  Default: 0.8  [0<=x<=1]
  --latitude FLOAT                Latitude of the reference point.
  --longitude FLOAT               Longitude of the reference point.
  --rank INTEGER                  The N stations closest to --latitude/--longitude, or the N best
                                  --name matches, best first.
  --distance FLOAT                The stations within this many km of --latitude/--longitude.
  --left FLOAT                    Select stations in a bounding box: its west longitude.
  --bottom FLOAT                  South latitude of the bounding box.
  --right FLOAT                   East longitude of the bounding box.
  --top FLOAT                     North latitude of the bounding box.
  --sql TEXT                      Select stations by a SQL WHERE clause over their metadata.
                                  Example: region='Sachsen'
  --station-window-end-buffer INTEGER RANGE
                                  Days after the end its catalogue publishes that a station is still
                                  kept for the window: 0 compares the end exactly. The start is
                                  compared exactly. Default: WD_TS_STATION_WINDOW_END_BUFFER if set,
                                  else two days up to daily, 62 for monthly and 732 for annual
                                  [0<=x<=3660]
  --format [json|geojson|csv|ndjson|html|png|jpg|webp|svg|pdf]
                                  Output format: json, geojson, csv or ndjson (the metadata, a line
                                  for each row, then the end) for data, html, png, jpg, webp, svg or
                                  pdf for a chart. Default: json
  --width INTEGER RANGE           Width of a rendered chart in pixels.  [x>=1]
  --height INTEGER RANGE          Height of a rendered chart in pixels.  [x>=1]
  --scale FLOAT RANGE             Scale factor of a rendered chart image.  [x>0]
  --target TEXT                   Export target URI, instead of stdout. Examples: file://data.csv,
                                  duckdb:///obs.duckdb?table=weather
  --if-exists [replace|append|fail|skip]
                                  What to do when --target already holds data: 'replace' (drop and
                                  rewrite, default), 'append' (add to it), 'fail' or 'skip'. Not
                                  every sink takes every value: files refuse 'append', and InfluxDB
                                  refuses 'fail' and 'skip' and accumulates under both of the
                                  others, nothing there clearing a measurement. Default: replace
  --pretty BOOLEAN                Pretty-print JSON with 4-space indentation, as REST's pretty=true.
                                  Default: false
  --with-metadata BOOLEAN         Add the units and the quality flags to the metadata block of
                                  JSON/GeoJSON output, which is always there. Default: false
  --debug BOOLEAN                 Log at debug level. Default: false
  --help                          Show this message and exit.

  Examples:

  # all stations with daily climate summaries, as JSON, CSV or GeoJSON
  wetterdienst stations --provider=dwd --network=observation --parameters=daily/kl --all
  wetterdienst stations --provider=dwd --network=observation --parameters=daily/kl --all --format=csv
  wetterdienst stations --provider=dwd --network=observation --parameters=daily/kl --all --format=geojson

  # stations by id, or by fuzzy name
  wetterdienst stations --provider=dwd --network=observation --parameters=daily/kl --stations=1048,4411
  wetterdienst stations --provider=dwd --network=observation --parameters=daily/kl --name=Dresden

  # the five stations closest to a point, or those within 25 km of it
  wetterdienst stations --provider=dwd --network=observation --parameters=daily/kl \
      --latitude=49.9195 --longitude=8.9671 --rank=5
  wetterdienst stations --provider=dwd --network=observation --parameters=daily/kl \
      --latitude=49.9195 --longitude=8.9671 --distance=25

  # only the stations with a record in a window, so the closest are not ones that closed long ago
  wetterdienst stations --provider=dwd --network=observation --parameters=daily/kl \
      --latitude=49.9195 --longitude=8.9671 --rank=5 --timestamp=2020-05

  # stations by region, or by a pattern in their name
  wetterdienst stations --provider=dwd --network=observation --parameters=daily/kl --sql="region='Sachsen'"
  wetterdienst stations --provider=dwd --network=observation --parameters=daily/kl \
      --sql="lower(name) LIKE lower('%dresden%')"

  # MOSMIX forecast stations
  wetterdienst stations --provider=dwd --network=mosmix --parameters=hourly/large --all

  # export to a spreadsheet
